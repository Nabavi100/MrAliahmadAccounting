# سیستم حسابداری شرکت تجارتی برادران نبوی

سیستم جامع حسابداری دو ارزی (افغانی و دالر)، خرید و فروش، مدیریت گدام و گدام امانی،
صرافی، طلبات و بدهیات، هزینه‌ها و عواید، دارایی‌های ثابت و سهامداران.

---

## اجرای برنامه

```bash
npm install       # نصب پکیج‌ها
npm run dev       # اجرای برنامه روی پورت ۳۰۰۰ (حالت توسعه)
npm run build     # ساخت نسخه نهایی در پوشه dist
npm start         # اجرای سرور (تولید)
```

| اسکریپت | کاربرد |
| --- | --- |
| `npm run dev` | اجرای برنامه همراه با سرور تلگرام |
| `npm run build` | ساخت نسخه تولیدی |
| `npm run typecheck` | بررسی کامل تایپ‌های TypeScript |
| `npm run smoke` | تست خودکار رندر همه صفحات (بدون نیاز به مرورگر) |
| `npm run test:api` | تست API ذخیره‌سازی روی سرور |
| `npm run test:e2e` | تست کامل: ذخیره خودکار، حفظ اطلاعات پس از پاک شدن مرورگر و دسترسی از دستگاه دوم |

> **نکته:** برنامه در حالت توسعه روی `0.0.0.0` گوش می‌دهد و آدرس‌های پروکسی/پیش‌نمایش را می‌پذیرد،
> بنابراین از طریق شبکه داخلی یا اینترنت (تانل) نیز قابل دسترسی است.

## میان‌بُرهای کیبورد

برای کار سریع‌تر، بدون استفاده از ماوس:

| کلید | عملکرد |
| --- | --- |
| `Ctrl + K` (یا `⌘ + K`) | جستجوی سراسری و اجرای سریع دستورات |
| `Ctrl + B` | باز و بسته کردن منوی کناری |
| `Alt + 1` … `Alt + 9` | رفتن به داشبورد، روزنامچه، فاکتورها، دریافت/پرداخت، مشتریان، گدام‌ها، صندوق‌ها، گزارش‌ها، تعاریف |
| `Alt + N` | فاکتور فروش جدید |
| `Alt + M` | فاکتور خرید جدید |
| `Alt + R` | رسید دریافت وجه |
| `Alt + P` | سند پرداخت وجه |
| `Alt + T` | انتقال کالا بین گدام‌ها |
| `Alt + S` | مدیریت کاربران و سطوح دسترسی |
| `Alt + H` | راهنمای همین میان‌بُرها |

میان‌بُرها بر اساس **کد فیزیکی کلید** کار می‌کنند، پس با کیبورد فارسی/دری هم درست عمل می‌کنند،
و هنگام تایپ داخل فرم‌ها به‌طور خودکار غیرفعال می‌شوند.

## جستجوی سراسری (Ctrl + K)

یک پنجره واحد که همزمان در موارد زیر جستجو می‌کند:

- **صفحات و بخش‌ها** — رفتن سریع به هر صفحه سیستم
- **عملیات** — صدور فاکتور، رسید، پرداخت، انتقال وجه، تبدیل ارز، پشتیبان‌گیری و…
- **طرف حساب‌ها** — با نام، شماره تماس، کد یا گروه (کارت حساب مستقیماً باز می‌شود)
- **کالاها** — با نام، کد یا گروه همراه با موجودی فعلی (کارتکس کالا باز می‌شود)
- **فاکتورها** — با شماره فاکتور، نام طرف حساب یا تاریخ

جستجو با حروف فارسی و عربی، اعداد فارسی و لاتین و حتی با کمی غلط تایپی کار می‌کند.

## استفاده در موبایل و تبلت

- منوی کناری در موبایل به‌صورت کشویی (Drawer) باز می‌شود و با انتخاب هر گزینه خودکار بسته می‌شود.
- نوار پائین صفحه چهار بخش پرکاربرد (داشبورد، فاکتورها، دریافت/پرداخت، گزارش‌ها) به‌همراه
  دکمه «+» برای عملیات سریع و جستجو را در اختیار می‌گذارد.
- جدول‌ها در صفحه‌های کوچک به‌صورت افقی قابل اسکرول هستند.
- صفحه‌ای که آخرین بار باز کرده‌اید، در مراجعه بعدی مستقیماً باز می‌شود.

## کارایی

صفحات سنگین (گزارش‌ها، داشبورد، نمودارها و پنجره‌های چاپ) به‌صورت **بارگذاری تنبلی (Lazy)** جدا شده‌اند؛
حجم بار اولیه از حدود ۶۵۹ کیلوبایت به حدود ۱۴۷ کیلوبایت (gzip) کاهش یافته و بقیه فقط در صورت
نیاز دانلود می‌شود — که روی اینترنت موبایل و شبکه‌های کند تفاوت محسوسی دارد.

## نگهداری و ذخیره‌سازی اطلاعات (روی سرور)

اطلاعات حسابداری **روی سرور** نگهداری می‌شود، نه فقط در حافظه مرورگر. یعنی:

- پاک کردن حافظه/تاریخچه مرورگر یا عوض کردن کامپیوتر، **باعث از دست رفتن اطلاعات نمی‌شود**؛
- از هر دستگاه دیگری (لپ‌تاپ، موبایل، دفتر دوم) همان اطلاعات دیده می‌شود؛
- از هر نسخه قبلی اطلاعات، به‌صورت خودکار نسخه پشتیبان روی سرور نگهداری می‌شود (۳۰ نسخه آخر).

### محل نگهداری فایل‌ها روی سرور

```
server_data/appdata/accounting-data.json     ← اطلاعات اصلی دفتر
server_data/appdata/backups/                 ← نسخه‌های پشتیبان خودکار (۳۰ نسخه آخر)
```

> این پوشه را در پشتیبان‌گیری‌های دوره‌ای سرور (Snapshot/rsync) قرار دهید. کافی است همین یک پوشه
> حفظ شود تا تمام اطلاعات دفتر قابل بازگردانی باشد.

### روش کار

1. برنامه هنگام باز شدن، آخرین نسخه اطلاعات را از سرور می‌خواند.
2. هر تغییری که در برنامه می‌دهید، پس از حدود ۲ ثانیه **به‌صورت خودکار** روی سرور ذخیره می‌شود.
3. اگر اینترنت/سرور قطع باشد، اطلاعات در مرورگر محفوظ می‌ماند و به‌محض برقراری ارتباط ذخیره می‌شود
   (نشانگر وضعیت در نوار بالای برنامه همیشه وضعیت را نشان می‌دهد).
4. اگر دو نفر همزمان کار کنند و نسخه سرور جدیدتر باشد، برنامه **به‌صورت خودکار روی اطلاعات جدید
   نمی‌نویسد**؛ ابتدا از شما می‌پرسد کدام نسخه معتبر است (نسخه دیگر هم پشتیبان‌گیری می‌شود).

### کلید دسترسی (توصیه مهم برای سرور اینترنتی)

اگر برنامه روی آدرس اینترنتی نصب است، حتماً متغیر محیطی `APP_DATA_KEY` را تنظیم کنید:

```bash
# روی سرور، قبل از اجرای برنامه
export APP_DATA_KEY="یک-کلید-طولانی-و-تصادفی"
npm run build && npm start
```

با تنظیم این کلید، تنها برنامه رسمی شرکت می‌تواند اطلاعات را بخواند یا ذخیره کند
(کلید به‌صورت خودکار در صفحه ورود به برنامه تزریق می‌شود، پس کاری برای کاربران لازم نیست).
اگر کلید تغییر کرد، فقط سرور را با مقدار جدید اجرا کنید؛ برنامه خودش همگام می‌شود.
در صورت نیاز، امکان ورود دستی کلید در بخش «پشتیبان‌گیری» وجود دارد.

### دسترسی از چند دستگاه

چون اطلاعات روی سرور است، چند کاربر می‌توانند روی اطلاعات یکسان کار کنند. برای تفکیک
مسئولیت‌ها از بخش «کاربران و سطوح دسترسی» برای هر نفر یک کاربر با مجوزهای اختصاصی بسازید
تا در «دفتر ممیزی» مشخص باشد چه کسی چه تغییری داده است.

## نکته درباره نسخه قبلی (انتقال اطلاعات)

اگر پیش از این ارتقا، اطلاعات را در مرورگر همان کامپیوتر ذخیره کرده بودید: کافی است یک‌بار برنامه
را روی همان کامپیوتر باز کنید. اطلاعات به‌صورت خودکار از مرورگر خوانده و روی سرور ثبت می‌شود
(پیام «اطلاعات موجود در این مرورگر به سرور منتقل و ذخیره شد» نمایش داده می‌شود). از آن پس
همه دستگاه‌ها همان اطلاعات را می‌بینند.
